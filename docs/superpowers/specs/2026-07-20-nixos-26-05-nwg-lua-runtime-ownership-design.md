# NixOS 26.05, NWG Displays Lua, and Runtime-Owned Desktop Config Design

## Problem

The system currently evaluates and runs NixOS 25.11 with `nwg-displays` 0.3.26. That version writes legacy Hyprland snippets to `~/.config/hypr/monitors.conf`, while this configuration loads only `hyprland.lua`. The generated layout is therefore ignored on reload, `nh os switch`, and login.

The mismatch is observable now:

- `monitors.conf` requests eDP-1 at `0x360`;
- the active Lua-controlled layout has eDP-1 at `0x0`;
- no local loader reads `monitors.conf`;
- no converter writes the host Lua file.

Nix/Home Manager also still creates or links several files that are generated by `nwg-look`, Matugen, Noctalia, or theme applications. Some out-of-store links point directly into the repository, so a runtime writer can dirty versioned files.

## Verified Upstream State

The `nixos-26.05` package set provides:

- `nwg-displays` 0.4.3;
- Linux LTS 6.12.96 through `linuxPackages_6_12`;
- NVIDIA stable 595.71.05;
- Hyprland 0.55.4 in nixpkgs.

Home Manager has a matching `release-26.05` branch.

Upstream `nwg-displays` 0.4.3 writes both legacy and Lua output:

- `~/.config/hypr/monitors.conf`;
- `~/.config/hypr/monitors.lua`, containing `hl.monitor({...})`;
- `~/.config/hypr/workspaces.conf`;
- `~/.config/hypr/workspaces.lua`, containing `hl.workspace_rule({...})` when workspace assignments are applied.

It then asks Hyprland to reload and restores both formats if the user rejects the confirmation dialog.

## Goals

- Upgrade the primary NixOS and Home Manager inputs from 25.11 to 26.05.
- Use the stock `nwg-displays` 0.4.3 package from NixOS 26.05; do not maintain a custom package override.
- Make NWG's generated Lua layout the persistent runtime authority after the first Apply.
- Keep the host-specific tracked Lua layout as a safe fallback when no generated runtime layout exists.
- Remove Nix/Home Manager ownership of all desktop-theme output paths shown by `nwg-look`'s export dialog.
- Prevent runtime theme applications from writing through out-of-store links into the repository.
- Preserve current dark appearance and the working HDMI configuration.
- Include the already approved SKWD graphical-session lifecycle fix in the same validated deployment.

## Non-goals

- Changing `system.stateVersion` or `home.stateVersion` from 25.11.
- Maintaining a fork or converter for `nwg-displays`.
- Making legacy `monitors.conf` the canonical Hyprland configuration.
- Forcing `GTK_THEME` globally.
- Managing runtime-generated GTK, cursor, monitor, or workspace files declaratively.
- Changing HDMI GuC policy, BIOS, monitor detection, or the selected Linux LTS family.

## NixOS 26.05 Upgrade

Change only the primary release inputs:

- `nixpkgs`: `github:NixOS/nixpkgs/nixos-26.05`;
- `home-manager`: `github:nix-community/home-manager/release-26.05`.

Refresh `flake.lock` for those inputs and any lock nodes that must follow them. Keep the dedicated `nixpkgs-zen70` revision pinned, because it exists for a separate Zen/NVIDIA compatibility constraint.

Keep every `system.stateVersion` and `home.stateVersion` at 25.11. Those values describe persisted-state compatibility, not the installed release.

The upgrade is accepted only if all graphical Lenovo outputs evaluate, the full `lenovo-hyprland` closure builds, Linux stays on the 6.12 LTS line, and the NVIDIA module builds. Runtime validation must confirm HDMI, Hyprland, SKWD, and NWG after reboot. Generation 106 remains the rollback target for the known-working NixOS 25.11 HDMI state.

## NWG Displays Lua Integration

### Runtime files

The following files are application-owned and must not be Nix/Home Manager links or activation outputs:

- `~/.config/hypr/monitors.conf`;
- `~/.config/hypr/monitors.lua`;
- `~/.config/hypr/workspaces.conf`;
- `~/.config/hypr/workspaces.lua`;
- `~/.config/nwg-displays/config`.

### Monitor loader precedence

The tracked `lua/monitors.lua` loader will use this order:

1. If `~/.config/hypr/monitors.lua` exists, load it with `dofile` and stop.
2. Otherwise load `~/.config/hypr/lua/monitors/<hostname>.lua`.
3. If neither exists, apply the generic preferred/automatic fallback.

This makes NWG's confirmed Apply persistent without letting it modify the repository. The current Lenovo host file remains a recovery fallback.

### Workspace loader

If `~/.config/hypr/workspaces.lua` exists, load it explicitly from the main Lua configuration. If absent, preserve current workspace behavior. Do not manage or seed the file.

### Failure handling

- NWG 0.4.3 keeps its own confirmation rollback for `.conf` and `.lua` outputs.
- A malformed runtime Lua file will be treated as a runtime configuration error visible through Hyprland config errors; the user can move it aside to recover the tracked host fallback.
- Deployment validation must preserve a copy of the last valid generated layout before interactive testing.
- Never point NWG's `--monitors_path` directly at a tracked `.lua` file.

## Runtime Ownership Boundary

Nix may install theme packages and theme applications. It must not create, seed, link, or overwrite the generated output files below.

### Remove activation seeds

Remove Home Manager activation creation for:

- `~/.config/gtk-3.0/settings.ini`;
- `~/.config/gtk-4.0/settings.ini`;
- `~/.gtkrc-2.0`;
- `~/.config/xsettingsd/xsettingsd.conf`;
- `~/.icons/default/index.theme`;
- `~/.config/gtk-4.0/gtk.css`;
- `~/.config/gtk-4.0/gtk-dark.css`.

### Remove managed GTK4 outputs

Remove these paths from `profileSpecificPaths` and delete their versioned output copies:

- `.config/gtk-4.0/noctalia.css`;
- `.config/gtk-4.0/dank-colors.css`;
- `.config/gtk-4.0/colors.css`;
- `.config/gtk-4.0/thunar.css`.

The strict boundary follows the user's `~/.config/gtk-4.0/*` requirement. Any desired GTK4 customization must be generated or copied by the owning runtime application, not linked from this repository.

### Remove managed default icon output

Remove `.local/share/icons/default` from host-managed icon subdirectories and delete tracked host `index.theme` copies. `nwg-look` and `orgm-themes` own the runtime default-icon file.

### Inventory

Keep or expand `localOnlyPaths` as documentation for runtime ownership, but do not treat that list as enforcement. Tests must inspect actual `home.file` inputs and activation scripts.

## Dark Mode

A fresh NWG Displays 0.3.26 window was captured after `nwg-look` export and is dark. The earlier light instance was launched at 16:05; GTK settings were exported at 16:07. Therefore no forced-theme fix is required.

The ownership change preserves the existing regular GTK3 settings file. New systems depend on `nwg-look` or the theme application to export their chosen theme. Runtime validation opens a fresh NWG window and confirms that it uses the selected GTK3 dark theme.

## SKWD Lifecycle

Implement the separately approved `2026-07-20-skwd-graphical-session-lifecycle-design.md` design:

1. import the Hyprland Wayland/session environment;
2. activate `graphical-session.target`;
3. let the existing target dependency start `skwd-daemon.service`;
4. confirm automatic wallpaper restoration.

Do not start the SKWD binary directly and do not reintroduce the removed bootstrap helper.
