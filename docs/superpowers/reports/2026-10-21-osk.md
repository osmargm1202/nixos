# Standalone Quickshell OSK — Envy and Jarq

## Goal
Provide a manual touch keyboard that works inside Rofi without replacing the existing shells, for Envy/Sway and Jarq/i3; shared Hyprland integration.

## Instructions
- Apply own changes and orgm-dot pull, user tests when ready.
- No OS switch, full Home Manager activation, commit/push or root input permissions.
- Preserve existing own unrelated diffs; do not replace remote checkouts.

## Discoveries
- Quickshell PanelWindow is cross-platform and nonfocusable. Dynamic WlrLayershell Overlay is used only when supported ([official API](https://quickshell.org/docs/v0.2.1/types/Quickshell.Wayland/WlrLayershell/)).
- Rofi X11 popup grabs block clicks to a separate OSK. i3-rofi and rofi-menu-lib now pass -normal-window; the existing i3 app owns the centered floating rule. normal-window is not a Rasi configuration property.
- Xvfb needs -noreset to retain the Jarq us/latam altgr-intl layout between setup and client startup.
- Both native tests use decoy-only menu input, so expected output proves actual typing rather than selection of an existing item.
- User runtime identity remains unregistered, so no agent-attributed Engram writes were performed. This report and the implementation ledger preserve the work instead.

## Accomplished
- Independent GPL-3.0-attributed adaptation of end-4 OSK interaction/layout, pinned upstream reference in UPSTREAM.md; no complete upstream shell or ydotool daemon.
- Fixed lower-left keyboard button and bottom-center swipe pill; Win+Ctrl+O shortcut.
- Spanish layout with ñ, acute/diaeresis, Shift/Caps/AltGr/Ctrl/Alt; Space, Backspace, arrows, Enter/Escape; repeat on navigation/delete.
- Resize +/- and hide; reset latches on hide; visible input engine error and manual retry.
- Persistent unprivileged native Wayland virtual keyboard; X11 XTest through xdotool. Atomic press/release, no clipboard use, no typed-text logging.
- Declarative engine package and compositor-specific user-service lifecycle; no OSK in console/server roles.

## Rulings and review disposition
1. Jarq uses unprivileged XTest with its us/latam intl layout rather than uinput; external layouts may need mapping changes.
2. Rofi/i3 uses normal-window and floating/centered rule because popup grabs block the OSK; focus-dismiss behavior differs from a grabbed popup.
3. No commit/push or full Nix activation was performed; permanent startup waits the next authorized activation.
4. AltGr is a curated Spanish symbol palette: explicit alternatives send Mod5, ordinary fallback keys send base, Shift does not add hidden level4. Uncommon physical level3/4 combinations need explicit additions.
5. Runtime-only units avoid shadowing future declarative service files; cost is no automatic startup after reboot until Nix activation.
6. Physical ergonomics/multi-monitor behavior remain user/hardware validation; cost may be later hit-area/output adjustments.
7. Single-instance was tested live on Envy, targets/backends evaluated, but logout/relogin and simultaneous displays were not exercised; startup/environment problems remain possible there.
8. Escape/repeat/resize gaps from review were closed by native tests; real lock boundary remains compositor responsibility and outside this OSK, not a promise of lock-screen keyboard support.
9. Pinned upstream URL/commit, attribution and complete GPL license are included; no independent licensing/legal audit was performed. Incorrect upstream provenance would require correction.
10. Prior shell/ScrollOverview diffs were deliberately excluded from this review and preserved; this task does not resolve unrelated pre-existing failures.

## Key Learnings:
1. X11 Rofi popup grabs and xdotool clearing held pointer buttons are separate causes of broken external OSK interaction.
2. Rendered AltGr labels must match the exact emitted XKB level; literal nonmatching Rofi output tests reveal backend divergence.
