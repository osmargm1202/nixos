# Shared Envy and Jarq On-Screen Keyboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Inline TDD, one final fresh review.

**Goal:** Deliver the approved independent Quickshell keyboard for Envy and Jarq, with a fixed button and bottom gesture; retain current desktops.
**Architecture:** Adapt end-4 OSK interaction/layout concepts under GPL-3.0 attribution, without its complete shell or Ydotool service. A persistent unprivileged Python engine handles atomic key taps through Wayland virtual-keyboard-v1; X11 uses xdotool/XTest without stealing focus. One nonfocusable Quickshell PanelWindow UI runs on Sway, Hyprland and i3/X11. Common Nix module deploys the engine/service and editable app manifest for both users.
**Tech Stack:** Python3/ctypes/libxkbcommon, Wayland protocol, XTest/xdotool, Quickshell0.3/QML, NixOS, native session tests.
**Spec:** Approved chat description plus user “DALE, PARA JARQ TAMBIEN”; research report docs/superpowers/reports/2026-10-20-envy-osk-research.md in canonical checkout. Includes manual control, Spanish, adjustable size, Rofi focus retention; excludes replacing desktop or lock/greeter keyboards.

## Global Constraints

- Canonical Envy=Sway, Jarq=i3/X11, OrgM=Hyprland; do not silently omit Jarq or switch compositor.
- No system switch/reboot/global HM activation/commit/push, no root/uinput permissions, no unsafe lock bypass.
- Existing own isolated worktree9279 reused; preserve previous task diffs and user's configs.
- Use private HOME/runtime/displays for native tests; no real password/history capture.
- UI must not take keyboard focus; keypresses atomic with all injected modifiers released per operation/close/disconnect.
- Apply own files with collision/content guards and orgm-dot backup; remote deployment only if existing access is available, otherwise report not physically tested/deployed remotely.

## Review Focus

- Rofi real keystrokes and menu retained while opening/touching keyboard; diagnose grabs, don't just screenshot UI.
- ñ/accents, Shift/AltGr, Space/Backspace/Enter/Escape and repeat; no stuck modifiers or arbitrary command execution.
- Service single-instance and display-specific lifecycle; no desktop services in terminal/server modes.
- i3 X11 must use XTest, not Wayland-only layer-shell assumptions.
- Lock screen remains secure; OSK normal panels cannot replace session-lock UI.
